Function Call & MCP 协议

一、Function Call

概念

“Function Call”（函数调用）是一种让大语言模型（LLM）能够与外部工具、API 或代码进行交互的技术。通过这种技术，LLM 不仅能回答基于其训练数据的问题，还可以执行特定任务或获取实时信息。

基本步骤

定义工具

  • 定义工具列表，给大模型配置工具；

模型决策

  • 大模型根据用户的 query 选择是否调用工具，若无需调用则直接返回用户答案；

工具执行

  • 若需要调用工具，返回结构化数据、工具的名称和参数；

结果返回

  • 手动执行工具调用，得到结果；

生成最终答案

  • 结合原有的 messages，给到大模型得到最终的回答。

实现方式

自定义 json schema

装饰器 tool 方式

基于 pydantic 的 tool 方式

二、MCP 协议

概念

MCP（Model Context Protocol，模型上下文协议）是由 Anthropic 在 2024 年 1 月提出的一套开放协议，旨在规范大语言模型（LLM）与外部数据源和工具交互的方式，用来在大模型和数据源之间建立安全双向的链接。

实现方式

MCP 角色

MCP 协议有两大核心角色：MCP 客户端和 MCP 服务端。

MCP 服务端（Tool Provider）

  • 角色：工具的提供者；
  • 职责：将一个或多个工具（本地函数，如Python函数）包装起来，通过一个标准的 MCP 接口暴露出去。它监听来自客户端的请求，执行对应的函数，并返回结果。

MCP 客户端（Tool Consumer）

  • 角色：工具的调用者或消费者（一般情况为大语言模型）；
  • 职责：连接到 MCP 服务端，查询可用的工具列表（自发现），并根据需要调用这些工具。

MCP 传输方式

stdio（标准输入/输出）

stdio 是一种非常经典和简单的进程间通信（IPC）方式。客户端启动服务端作为一个子进程。

  • 工作原理：通过写入子进程的标准输入（stdin）来发送请求，并通过读取子进程的标准输出（stdout）来获取响应。此方式简单高效，无需网络开销。
  • 传输特点：本地双向传输；
  • 适用场景：非常适合在本地环境中，将一个命令行工具或脚本快速封装成一个 MCP 服务。

SSE（Server-Sent Events）

SSE 是一种基于 HTTP 的单向推送协议，它允许服务器在保持连接开放的情况下，持续向客户端发送事件流。

  • 工作原理：客户端发起一个 HTTP 请求，服务器接收请求并保持连接，然后以 text/event-stream 格式将响应数据流式传输给客户端。这在 MCP 中被用来实现请求与响应的通信。
  • 传输特点：远程单向传输；
  • 适用场景：适用于分布式或网络环境，当服务需要部署在远端，并通过网络供多个客户端访问时。
    此传输方式已逐渐被 Streamable-HTTP 方式取代。

Streamable-HTTP

Streamable-HTTP 是 MCP 提供的另一种基于 HTTP 的传输方式，它同样用于网络通信。

  • 工作原理：客户端通过 HTTP 请求与服务器通信。与 SSE 的主要区别在于其传输格式和机制可能有所不同，但核心目的都是通过网络实现 MCP 协议。
  • 传输特点：远程双向传输；
  • 适用场景：适用于需要通过网络进行通信的分布式应用。
